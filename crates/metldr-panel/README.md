# Rust panel module

The crate implements the Chrome side panel and its background message handling in Rust and WebAssembly. It provides streamed results, retained assistant messages and tool activity, browser action decisions, provider and installed agent settings, cancellation and saved run restoration. Native work and saved run ownership stay with the paired companion. The normal extension build includes this panel at `panel.html`. The toolbar initially opens the existing page tools while their Rust migration continues.

Run `make check-panel` to check the Rust module. Run `make panel-wasm` to build its browser bindings into `crates/metldr-panel/pkg`. Both commands use the pinned Rust toolchain. The build also needs the `wasm32-unknown-unknown` target and `wasm-bindgen-cli` version 0.2.128, matching the crate dependency. Set `WASM_BINDGEN` to the generator executable if it is outside your path. Set `PANEL_TARGET_DIR` to choose the Cargo build directory.

The generated `metldr_panel.js` exports `start_panel` and `accept_panel`. Initialize the generated module before calling its exports. The panel document must be `panel.html` within the same extension, with an `app` element and the expected browser event bindings. The background passes only its named connected extension ports to `accept_panel`. Other extension ports keep their existing owner. The small Chrome binding opens the selected panel directly from its command callback, preserving the required user gesture. The module validates the sender and owns the native connection to `io.metldr.first_flow` using wire version 16. A paired, registered companion and the extension permissions are required for native execution.

The UI bridge exposes `active_run()` after a fresh snapshot. Its handle observes the saved task through ordered events and stops only that task. The agent adapter uses `connectAgent()` to attach without submitting another request. Detaching a view releases its subscription while native work continues. Detach the agent and free the active handle when closing its view. Reconnecting requires a fresh handle. Update the extension and companion together.

The chat adapter treats each Rust message snapshot as the complete ordered message list. It replaces old activity as well as text, so corrections cannot leave stale activity in the conversation. Agent clones keep the same behavior.

New chat creates an empty conversation. Chats lists saved conversations with search over loaded pages and a More control for further pages. Selecting a conversation restores its saved page and results while preserving the composer draft. Active work blocks switching. A lost confirmation keeps the exact change request for explicit Retry and blocks new work until its outcome is known. Saved work reads complete results separately from the live task. The current navigation remains provisional while the reference interface migration continues.

Choose a configured provider's Page questions entry to ask about the saved page. The source menu's Summarize current page control captures the selected page and uses that same provider. The selected model and endpoint are shown in execution details. Completed answers stay scoped to the saved page and provider selection. Text requests have no browser actions. Browser task entries and installed agent sessions remain separate choices. The owned test model is available only when its fixture is configured and is labelled before use.

The Codex composer offers Default and Plan. Default keeps the native collaboration settings, and Plan requests the effective native model's Plan mode. The panel can answer nonsecret native questions, required string MCP forms and separate MCP tool approvals. Stop withdraws pending input. Replies remain transient, while normal model and tool output can repeat an answer and follow the existing output storage policy. Other form types and secret questions remain unsupported.

The module uses the shared `metldr-conversation` model. Streaming updates retain message identities and observed tool order. Copy reads current validated output and reports when the copied result has changed. The Chrome background validates browser context and grants before browser commands. Provider credentials belong to the native companion rather than page scripts.

The named web preview displays the interface but cannot start native work. If the panel connection cannot start, the panel shows its unavailable state and disables task controls. Reload panel retries startup. Actual provider and browser tasks require the installed extension and its paired companion.

Run `npm run build` at the repository root to build the complete extension into `dist`, then load that directory at `chrome://extensions`. Press Alt+Shift+M to open the Rust browser agent, or Ctrl+Shift+Y to return to the current page tools. Chrome lets you change shortcuts at `chrome://extensions/shortcuts`. The Rust path requires the [native companion](../metldr-companion/README.md), registered separately for the loaded extension ID. Building does not install or register it.

The build retrieves pinned fonts and required dependency notices through the Rust asset helper. Generated output stays outside Git. Existing Gmail, PDF, dictionary and local inference interfaces continue to use their current entry while their replacements are unfinished. Complete visual parity and native Windows and macOS verification remain unfinished.
